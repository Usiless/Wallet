## Behavior

- The coordinator includes elapsed request identities for still-open enabled obligations. Android only schedules future instants; a newly introduced elapsed request is marked skipped, while an unchanged previously known delayed request retains its prior delivery eligibility. This prevents historical reminder floods when the next alarm wakes.
- Each native request now retains its own persisted generation across unchanged replacements. Unrelated obligations changing or ordinary resume do not cancel an existing notice or invalidate its tap. Removed and meaningfully edited entries invalidate the former generation before selectively cancelling their notices and alarms. The request signature includes the obligation revision as well as title, body, date and obligation ID.
- Delivery marks remain persisted, exclude repeated delivery, and are pruned to the currently reconciled request IDs. Historical new requests are marked done without notifying. Previously delivered matching request IDs remain done even if edited.
- Future alarms are refreshed to keep the 400-entry window bounded; unchanged already-due delayed alarms are not cancelled by foreground replacement.
- `consume` and alarm delivery validate the matching entry generation. Taps still only return the obligation ID and have no financial write. `onNewIntent` signals the existing capture callback after saving the new intent, ensuring the foreground app consumes the action even without a lifecycle transition; existing app ordering consumes the action before reconciliation.
- Legacy unsupported reminder settings are excluded individually by the coordinator, which still replaces the entire native agenda using the remaining valid open obligations and returns false. It neither clamps the setting nor leaves paid/cancelled obligations in an old agenda. Domain/UI range alignment is owned by the other tasks.
- Restore removes or changes corresponding reminders according to the restored set and revisions. A restored byte-identical open obligation remains valid; no additional restore epoch was introduced.

## Scope and limitations

Native tests exercise the actual pure replacement policy used by the agenda, including per-entry identity retention, selective invalidation, new historical skips, known delayed eligibility and removed entries. They do not run NotificationManager, AlarmManager, encrypted SharedPreferences or Android intent dispatch. Direct Kotlin compilation checks integration type/syntax correctness only, and is not a full Gradle Android build. Physical/emulated Android checks remain required for real notification visibility, foreground/cold taps, permissions, reboot, timezone/clock changes, process death and OEM delivery restrictions. Full Flutter suite/integration validation is left to the parent task's consolidated run to avoid duplicated concurrent suites.
