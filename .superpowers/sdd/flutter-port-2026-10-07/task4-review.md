## Confirmed defects

1. **P1 — Budget cards expose a button without a semantics activation action.** `lib/features/budgets/presentation/budgets_screen.dart:173–181` wraps the card in `Semantics(button: true, excludeSemantics: true, label: ...)`, but puts its only `onTap` on the child InkWell. Flutter's local SDK documentation states that excludeSemantics ignores all child semantics nodes (`packages/flutter/lib/src/widgets/basic.dart`, excludeSemantics documentation). The wrapper supplies no replacement `onTap`, so assistive technology gets the label/role but loses the child's tap action. This contradicts the required accessible budget detail and labels. Add the same detail callback to the outer semantics or preserve/merge the child's action; verify a semantics tap opens detail. Confirmed from actual source/SDK semantics contract; no Android TalkBack run claimed.

2. **P1 — Available money loses significant digits at 320 px / text 2x.** `docs/evaluation/flutter-port-2026-10-07/flutter-inicio-320-2x-before.png` visibly shows `727.0…` instead of `727.000 ₲`. Current `_HeroBalance` passes `maxLines: null`, but `MoneyText` still sets `TextOverflow.ellipsis` and the indivisible number cannot fit the available line. Source precedes capture timestamp; controller confirms this capture was exported with the same maxLines:null source. This is therefore an observed current defect, not merely inferred from an earlier snapshot. A financial summary must preserve the entire amount at enlarged text. Reflow/provide the amount enough width without truncation; verify the whole number remains visible at 320/2x, including a larger and negative balance. Widget absence-of-exception alone cannot establish this.

3. **P2 — Upcoming-payment heading and descriptions break within words at 320/2x.** Dashboard `Row` at lines 91–103 puts the heading beside a nonflexible `Ver todos`; `ListTile` at lines 110–123 reserves a trailing amount beside the title. The supplied 320/2x capture shows `Próxim` / `os` / `pagos`, and the description broken into `Servicio` / `de mant` / `enimient` with more content below the visible viewport. The other two captures show readable lines at normal scale. This is a concrete responsive defect rather than dislike of spacing: essential payment names become laborious to scan at the explicitly required enlarged size. Stack the action and heading, and move amount below description when measured width/text scale requires it. Confirm both of the next two payments remain readable by scrolling; no need to shrink the user's chosen text size.

4. **P2 — Missing payment data is presented as zero financial obligation.** Dashboard lines 44–59 computes `open` from `payments.value ?? []`, then displays `Pendiente del mes = 0` and `Patrimonio total = netWorth` at lines 77–88 before payment data exists or when an initial load fails. Loading/error feedback only appears below `Próximos pagos` (105–109). Thus an initial error leaves precise-looking but unsupported summary values, and initial load temporarily overstates financial wealth. Gate these two dependent amounts on usable payment data or keep an explicit unavailable/loading state. Available money can remain independent. Source-confirmed branch; no additional reproduction needed.

## Spec checks that passed source inspection

- Inicio computes available from included noncredit balances, month pending from remaining current-month obligations, and wealth from net balances minus **all** remaining obligations. It sorts open obligations by due date and takes two; removes account/history lists. Upcoming entries open detail, `Ver todos` opens payments, inbox action remains.
- Cuentas uses cards with adaptive one/two-column sizing; preserves Pagar tarjeta, Ver movimientos and Administrar, archive filters and savings inclusion management. Direct create FAB remains. Loading balance fallback to initial balance is existing financial UI behavior outside the specific new Dashboard finding; not used to claim complete financial-state reliability.
- Root titles are absent in Dashboard, Accounts root, Transactions, Analysis and Settings root. Actions remain in Transactions/Reports appbars. Account detail retains title and automatic back affordance. Router preserves five destinations and wide-screen NavigationRail. Captures render Dashboard directly, so they do **not** visually verify shell navigation/system insets.
- Inicio and Movimientos use the same MovementFab. It renders three individual extended FABs, closes on Escape, outside tap, group focus loss and Back, and returns focus on its normal close path. It respects disabled animations. Existing focus test explicitly covers Escape focus return and focus moving outside; no claim of TalkBack/device focus verification or route-return verification.
- Budget arcs share one radius, scale by max(1,total), use primary/error and pending opacity .42. Source/test examples cover 250% fully pending (40/60), 300% paid (1/3–2/3), 340% mixed, zero and negative ratio. Central percentage remains real rather than capped; no explanatory legend. Detail supplies paid/pending/target values and existing edit/recurrence remains. Theme uses green primary/red error schemes. Existing tests were inspected, not re-executed by this reviewer.
- Reports show ledger actual income/net expense separately from `Pendiente`. Report service sums only remaining uncancelled obligations in the selected due-date period/account/category. Paid amounts stay in ledger totals and are not added again from obligations. This review confirms calculation separation in current source, not a new independent exhaustive financial regression result.
